# tests/CLAUDE.md

Run with `uv run --group dev pytest`. CI runs them as the `run-tests` job in `.github/workflows/checks.yml`.

## What the tests cover

Only the parts that need no Discord connection: config loading, `Playlist`, saved playlists (`tests/test_playlists.py`, against an in-memory database), `Song` and how it refers to a saved playlist (`tests/test_song.py`), library search/stats, the browse cursor, `CachedLookup`'s lookup policy through a fake backend and clock (`tests/test_cached_lookup.py`), library enrichment's Last.fm and Spotify parsing and `clear_caches()`, over a fake Last.fm session and a fake enrichment Spotify client (`library_metadata._enrichment_client`), plus file reads kept on their own pool so a stalled Spotify cannot starve them, and the enrichment Spotify client's low limits (real spotipy clients) against the playback client's defaults (`tests/test_library_metadata.py`), the tag/expiry/URL parsers, the audio tag and artwork readers on real WAV, AIFF, WMA, MP3, FLAC and MP4 files tagged with mutagen at test time (`tests/test_audiotags.py`: front-cover choice, PNG/JPEG mapping, the size cap, no cover, WMA artwork reading as none, and a corrupt file never raising; the MP3 and WAV files are built in-test, the AIFF, WMA, FLAC and MP4 files are tiny silent untagged fixtures under `tests/fixtures/` - `silent.aiff`, `silent.wma`, `silent.flac`, `silent.m4a` - hand-built because mutagen cannot create them, so CI needs no ffmpeg), `loader.preload` with `_load` monkeypatched, and `_load(Lane.PRELOAD, ...)` dispatching to the preload lane (`tests/test_loader_preload.py`), `_load_song`'s no-result failures, a failed search being `SONGINFO_ERROR` and an empty one `SEARCH_NO_RESULTS` (`tests/test_loader_no_result.py`), the `d!search` reply telling the same two apart (`tests/test_search_command.py`), the loader's worker-pool recovery per extraction lane - a break rebuilds only that lane, once per crash, retried once, `LOADER_CRASHED` on a second break, none after shutdown - and `init()`'s concurrent warm-up of both lanes (also when one warm-up raises), through fake executors (`tests/test_loader_recovery.py`), the worker's network limits (`tests/test_worker_network_limits.py`: a failed Spotify lookup becoming a `SongError`, the Spotify session's capped 429 retries against a local server and `build_spotify_api`, and `get_session()`'s total timeout), the Discord attachment extractor's time limit and playlist shape (`tests/test_discord_extractor.py`: stalled, slow or failing login and fetch becoming `DownloadError` or `SongError`, over a fake `HTTPClient`), the permission and voice checks (voice joined only after them, through fake voice channels), which commands are joining commands (`tests/test_checks.py`: exactly the marked ones; an unmarked command or a player button never connects or moves and never refuses on voice it does not need, and a player button is refused with `NOT_CONNECTED_MESSAGE` while the bot is out of voice; a search pick connects), the guild whitelist, the guild settings descriptor table and the `d!setting show` embed it drives (`tests/test_settings_table.py`, on a fake guild), the guild session registry, the `d!search` results view (`tests/test_search_view.py`), the library browse view (`tests/test_library_browse_view.py`: a failed edit or defer undone, clicks during an in-flight enrichment edit accepted and a second click during a draw turned away, a stale enrichment never drawn, stale-scope components ignored, embed length limits, and the timeout edit through the last accepted click), a `MusicButton` click deferring before its checks, with only a pick acting in a joining command's name (one overriding the `join` hook) joining voice after them (`tests/test_music_button.py`), `AudioController` built through the seam below, the owner-command output helper `run_and_report` (`tests/test_owner_command_output.py`: real `sys.executable -c` children on a fake context; `d!update` calling it with `git pull`; `d!ytdlp` no longer registered), and a few command callbacks (`d!reset`, `d!restore`'s replies, the `d!setting <name>` subcommands, generated from that table: their confirmations, error replies, `vc_timeout` edit gate, slash parameters and prefix argument conversion, in `tests/test_setting_subcommands.py`; the prefix `setting` group's dispatch through discord.py's real `Group.invoke`, in `tests/test_setting_group.py`) driven on a fake context. They also cover `MusicBot.close()` joining the loader off the event loop, and `update_views`' per-guild isolation (`tests/test_update_views.py`: a failing guild's view update is logged with its name and a traceback, the others still update). They also cover the developer cog (`d!execute` capturing only its own prints, in `tests/test_developer_commands.py`; the whitelist subcommands' replies and owner checks, in `tests/test_guild_whitelist.py`; their `FakeBot`/`FakeCtx` live in `tests/developer_fakes.py`), the playlist gate on the `d!playlist` group and subcommands (in `tests/test_checks.py`), `SongError` replies and the `on_command_error` backstop (`tests/test_song_error_replies.py`), the button plugin's reaction handling (`tests/test_button_plugin.py`) and the guild-only app-command tree (`tests/test_bot_guild_only.py`). There is no integration coverage of the bot itself.

## The controller seam

`tests/controller_seam.py` builds an `AudioController` over a stub `musicbot.loader`, a fake bot/guild/voice client and a `tmp_path` cwd. While it is open, it forces `config.ANNOUNCE_DISCONNECT` off. Use it through the `controller` and `stub_loader` fixtures rather than building a controller by hand.

`tests/controller_helpers.py` holds the controller helpers the test modules share (`_settle`, `_songs`, `_queue`, `_run`, `_run_intent`, `_backup`, `_preloaded`, `_titles`, ...) and the `Music._play_song` fakes `play_ctx` and `ProcessController`; import them from there, never from another test module.

`tests/db_seam.py` holds `in_memory_db(settings)`, an async context manager yielding a sessionmaker over a fresh in-memory sqlite database migrated by `settings.run_migrations`; the saved-playlists and AudioController tests share it.

`tests/setting_fakes.py` holds the fakes the setting test modules share (`fake_bot`, `FakeDbSession`, `fake_channel`, ...); import them from there, never from another test module.

## Discord fakes

`tests/discord_fakes.py` holds the shared Discord stand-ins - the click `FakeInteraction`, `make_bot`, and the voice fakes (`VoiceGuild`, `FakeVoiceChannel`, `FakeVoiceClient`) - plus `http_error`, a 5 s-bounded `run(coro)` and `PLAYER_BUTTONS`, the player view's button ids. Import them rather than writing a per-file copy.

## Shared helpers

`tests/helpers.py` holds `run()` (a coroutine run through `asyncio.run` with a 5 s bound) and `FakeClock`. Import them with `from helpers import ...`.

## Subprocess probes

`tests/test_import_inert.py` runs fresh-interpreter subprocesses to check that importing `musicbot` changes no process-global state, that the entrypoint wraps stdout/stderr before `bot.run()`, that `MusicBot` can be built with no current event loop, and the loader's `init()`/`shutdown()` lifecycle, which starts real extraction workers (one per lane). `tests/test_loader_lanes.py` holds one real lane with a flag-file blocker: a preload completes while the load lane is held, and a worker killed in either lane leaves the other lane's in-flight and next calls intact while the killed lane's next call succeeds after its rebuild.

## The Config/dotenv trap

`Config.load()` calls `load_dotenv()`, and python-dotenv's `find_dotenv()` walks up from the calling module's file, not from cwd. A test that touches `Config` must redirect both `find_dotenv` and `load_dotenv` (see `tests/conftest.py`), or it reads the developer's real `.env`.
