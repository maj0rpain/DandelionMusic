## The controller seam

`tests/controller_seam.py` builds an `AudioController` over a stub `musicbot.loader`, a fake bot, guild and voice client (`ControllerBot`, `ControllerGuild`, `PlaybackVoiceClient`) and a `tmp_path` cwd, and builds the controller around a `RecordingPanel` (its `announced`, `skipped` and `ended` are what the controller tests assert on), or around the `make_panel` given - the `expired_panel_seam` fixture passes a real `PlayerPanel` whose channel fails with an expired token. While it is open, it forces `config.ANNOUNCE_DISCONNECT` off. Use it through the `controller` and `stub_loader` fixtures rather than building a controller by hand.

Race tests drive `Playback` through this controller seam (the fake voice port and stub loader), never by reading its private attributes.

`tests/controller_helpers.py` holds the controller helpers the test modules share (`_settle`, `_songs`, `_queue`, `_run`, `_run_while_playing`, `_song`, `_backup`, `_preloaded`, `_titles`, `_no_idle_timer`, ...), `command_ctx`, the fake command context for `Music` callbacks (`controller=None` for a command that reads no controller), and `ProcessController`, a guild-less controller whose `process_song` returns or raises a set result; import them from there, never from another test module.

`tests/db_seam.py` holds `in_memory_db(settings)`, an async context manager yielding a sessionmaker over a fresh in-memory sqlite database migrated by `settings.run_migrations`; the saved-playlists and AudioController tests share it. It also holds `seed_whitelist(factory, *ids)` and `seed_settings(factory, *ids)` (a default `GuildSettings` row per id), `with_db(test)` (runs `test(factory)` under `in_memory_db` in one event loop and returns the result; it imports `musicbot` and `helpers` inside the function, so the module imports neither at module level) and `FailingSessionFactory(inner, method, error)`, the one failing-session wrapper: the named session method (`"commit"` or `"flush"`) of each session raises `error` (an exception or a zero-argument callable making one) only while its `failing` attribute is true (true by default; while false the real method runs), and `attempts` counts the calls; the guild whitelist, saved-playlist and guild settings tests (`test_setting_writes.py`, `test_settings_load_many.py`) share it. It also holds `run_musicbot(monkeypatch, listed, guilds, scenario, fail_register, fail_settings)`, the real-`MusicBot` harness built on `with_db` (whitelisted ids, optional guilds, a `scenario(bot)` defaulting to `on_ready`, failure switches), returning a `MusicBotRun` of the registered ids, the panel starts and readiness; the `on_ready` and whitelist-admission tests share it.

`tests/setting_fakes.py` holds the fakes the setting test modules share (`fake_bot`, `FakeDbSession`, `fake_channel`, ...); import them from there, never from another test module.

## Shared helpers

`tests/helpers.py` holds `run()`, the suite's one bounded coroutine runner (a coroutine run through `asyncio.run` with a 5 s bound), `FakeClock`, `RedirectFollower` and `fake_redirect_follower(monkeypatch, result)` (a recording fake of `loader.resolve_redirects`, patched in), `plain_song` (a plain titled YT-DLP `Song`, the title defaulting to "a"), `imported_names(module, *, skip_type_checking=False, module_level_only=False)` (the names a module's source imports, read from its AST: each `import x`, and each `from m import n` as `m` and `m.n`; `skip_type_checking=True` skips `if TYPE_CHECKING:` blocks, for the import-seam tests; `module_level_only=True` skips imports inside function bodies, keeping the module-level ones), `imported_roots(module, *, skip_type_checking=False, module_level_only=False)` (the first dotted part of each of those names, same flags; a relative import's root is `""`), `type_checking_imports(module)` (the unparsed statements inside every `if TYPE_CHECKING:` block, at any depth, in source order: the blocks `skip_type_checking=True` skips), `attribute_names(module)` (every `name.attr` access on a plain name, as `"name.attr"`, e.g. `"discord.ui"`), `shell_commands(text)` (the shell commands in a text, continuations joined, split on `&&` and newlines), `dockerfile_commands(text=None)` (the instructions of `text`, the repo Dockerfile by default: continuations joined, blank and `#` lines dropped, the keyword upper-cased and followed by one space, so callers compare the uppercase keyword and do not re-normalise) and `REPO_ROOT` (the repository root, a `Path`) and `assert_logged_with_traceback(err, message)` (asserts `message` is in the captured stderr `err` and precedes its first `Traceback`: the failure-log line with its traceback; it fails when the message is missing, follows the traceback, or `err` holds no `Traceback`). Import-seam tests read a module's imports only through the four import helpers (`imported_names`, `imported_roots`, `type_checking_imports`, `attribute_names`); never hand-roll an AST walk. Import them with `from helpers import ...`; never define a per-file `run(coro)`. `tests/test_bounded_runner.py` enforces this: it fails on a bare `asyncio.run`, `asyncio.runners.run`, `asyncio.Runner` construction or `run_until_complete` call, or a module-level `run` definition, outside `helpers.py`. A deliberately unbounded call carries `# unbounded: <reason>` on the line where the call starts.

Import each shared test-helper module (listed below) in a single `from <module> import ...` statement, in one final block after the third-party, `config` and `musicbot` imports. The one exception: where the import depends on setup code (a `sys.path` or monkeypatch prelude), the helper block, still one block, goes directly after that setup code.

A shared test-helper module is any of `discord_fakes`, `helpers`, `developer_fakes`, `setting_fakes`, `controller_seam`, `controller_helpers`, `db_seam`, `library_fakes` and `message_link_fakes`. No two of them define the same top-level class, function or module-level variable, and no class, function or module-level variable in a test module takes a public top-level name of one of them: a fake whose shape differs takes a distinct, descriptive name (`EditingInteraction`, `CountingVoiceChannel`, `RespondedInteraction`), and one with the same shape imports the shared one. `tests/test_fake_names.py` asserts both.

`tests/message_link_fakes.py` holds the message-link gate's fakes (`LinkGuild`, `LinkChannel`, `LinkThread`, `CountingThread` (a `LinkThread` recording each `fetch_member` id in `lookups`), `LinkMember`, `perms`, the Discord API fake `FakeHTTPClient`, `gated_track` (a track through the real gate), `install_fake_discord_client` (resets it and installs it as the extractor's client) and the `LINK`/`FOREIGN_LINK`/`GUILD_ID`/`CHANNEL_ID`/`OTHER_GUILD_ID` constants).

`tests/library_fakes.py` holds `library_song(title, **fields)`, a `LibrarySong` with `None` defaults except `filename` (`<title>.flac`) and `fmt` (`FLAC`), that rejects unknown fields, and `external_stats(**fields)`, an `ExternalStats` with `None` defaults (`tags` `()`), that rejects unknown fields; the library test modules import them.

## Subprocess probes

`tests/test_import_inert.py` runs fresh-interpreter subprocesses to check that importing `musicbot` changes no process-global state, that the entrypoint wraps stdout/stderr before `bot.run()`, that `MusicBot` can be built with no current event loop, and the loader's `init()`/`shutdown()` lifecycle, which starts real extraction workers (one per lane). `tests/test_loader_lanes.py` holds one real lane with a flag-file blocker: a preload completes while the load lane is held, and a worker killed in either lane leaves the other lane's in-flight and next calls intact while the killed lane's next call succeeds after its rebuild.

## The Config/dotenv trap

`Config.load()` calls `load_dotenv()`, and python-dotenv's `find_dotenv()` walks up from the calling module's file, not from cwd. A test that touches `Config` must redirect both `find_dotenv` and `load_dotenv` (see `tests/conftest.py`), or it reads the developer's real `.env`. The conftest builds the session's global `config` with `find_dotenv` stubbed to `os.devnull`, and every subprocess probe starts with `NO_DOTENV_PRELUDE`, which does the same in the child and in any worker it spawns, so the real `.env` never loads during the test session; tests that build their own `Config` still go through `config_factory`.
